The ML application

Predict a logical outcome from error evidence

Training: fit a decoder using input features and known binary outcomes.

Inference: give the fitted model the same kind of input features to predict an outcome.

Evaluation: compare predictions with held-out actual outcomes. Actual outcomes are never input features.

QEC in plain language

Parity checks reveal evidence of errors

No prior quantum course required
Physical qubits are noisy

Logical information is protected across several physical qubits.

A parity check is like a checksum

Ancilla qubits record check outcomes without directly reading the protected information.

A syndrome is a pattern

Several check outcomes together provide clues about where an error may have occurred.

Simplified repetition-code intuition
q0data
q1data!
q2data
check s0q0 ↔ q1
check s1q1 ↔ q2
Syndrome 11 suggests a fault near q1

Four decoders: belief matching, correlated matching, PyMatching, tensor network contraction.

Decoder error = prediction ≠ actualA fired detector is evidence. If actual = 1 and prediction = 1, the decoder is correct.

QASMBench: columns you extract

Three circuit families, source + transpiled variants. Each table describes circuit structure.

circuit_id, benchmark_name, variant
Identify the circuit and its version.
qubit_count, measurement_count, two_qubit_gate_count
Describe declared qubits and executed operations.
ancilla_qubit, data_qubits, syndrome_bit
Who measures which parity, and where the result goes.
condition_register, condition_value, gate, target_qubit
Which measured syndrome activates which recovery.

No shot labels or shared shot IDs. QASMBench informs Gold’s circuit relations.

Parquet: an industry-standard table format

An open binary format that stores data by column, preserves types and compresses well. Tools can read selected columns efficiently. Silver and ML use it for compact, typed hand-offs.

Open with Pandas or PyArrow. Parquet is a file format. Gold remains your PostgreSQL database.
